# Notebook 工作台开发记录

日期：2026-10-29。沿用阶段 2b 的真实容器与反向通道，新增 Notebook 场景；不扩大到真实支付。

## 已完成

- 固定主依赖版本的 JupyterLab + NumPy 镜像、构建命令及完整依赖版本快照。
- 机器创建时选择环境模板，已有空闲 Docker 机器可原地切换；运行中和待清理时禁止切换；切换后撤销旧凭据。
- Jupyter 监听容器内部 localhost，无宿主端口；命令与 Notebook 内核均在订单容器内执行。
- 页面/文件 HTTP 与内核 WebSocket 经 agent 反向中继，保留二进制协议、正文、必要响应头和下载行为。
- 平台登录与订单访问会话双重验证、租客权限、来源检查、会话有效期、连接数量和消息大小限制。
- 默认中文 welcome.ipynb 示例，工作台展示模板与 Notebook 入口；外围等待状态区分“页面已加载”和“内核真正就绪”，准备完成前阻止误操作。
- 订单结束、退出登录、会话失效或 agent 断线关闭访问；工作目录随订单容器销毁。
- 版本 3 数据库迁移和升级前快照，旧机器默认 Python，不覆盖既有账本。

## 排查与修正

初期原生页面可以显示，自动化过早触发执行时偶发无输出。协议日志证明 HTTP、内核初始化和二进制回复都能转发，进一步检查发现 Notebook 的 sessionContext 尚未就绪，页面局部“Idle”不足以作为可执行标准。

已加入明确的内核就绪状态，准备时禁止交互；自动化等待同一状态后运行。同时把首次加载 HTTP 改为有界排队、每条内核连接改为独立中继，避免资源请求峰值和连接关闭相互干扰。

加入就绪门槛后，Notebook 完整流程连续重复三次通过。此前出现过失败，未将其隐藏或计作通过。
