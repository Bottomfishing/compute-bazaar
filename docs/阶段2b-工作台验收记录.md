# 容器工作台首版验收

日期：2026-10-29。本轮从 mock 调度推进到受控 Docker 工作台，不代表所有阶段 2/3 功能或公网运营已完成。

## 已实现与验证

- 三种执行器：mock、真实 Docker CPU 沙箱、真实 Docker NVIDIA GPU 容器。
- 本机实测 RTX 5050 Laptop GPU（8151 MiB），Docker 容器中能查询设备名称；没有执行训练或显卡压力负载。
- 固定 Python 镜像摘要、限制 CPU/内存/进程/tmpfs、无外网、只读根目录、cap-drop ALL、no-new-privileges；命令在容器内以 UID 1000 执行。
- 容器内独立租约看门狗，普通终端用户无法更改租约；agent 更新采用原子替换。租约到期退出，确认清理后释放资源。
- agent 主动发起认证 WebSocket，无需映射工作台宿主端口。控制面仅转发协议，不执行用户 shell。
- 一次性访问票据与订单/租客绑定的短期会话；凭据只存哈希；命令、文件、在途结果均受订单状态约束。
- xterm.js 输出终端和逐条命令输入；本地文本脚本导入、保存、运行、文件列表、打开与下载。界面明确显示 mock/CPU/GPU 模式及文件删除规则。
- 真实容器下单必须由机主邀请已注册账号；未受邀返回 403。
- schema_version 升到 2，新增访问记录与邀请；主库已做在线备份与 before-v2 一致快照。
- 容器名称和标签按控制面地址、机器、订单隔离；测试每轮独立数据库，避免真实 GPU UUID 在历史测试数据中重复登记。物理 GPU 唯一绑定规则保持。

## 本轮修正的实际问题

- Docker 不存在对象错误文本大小写不同：统一识别，保证停止操作幂等。
- 终端自适应与自动高度相互触发：改用固定输出高度，保持手机缩放并避免布局循环。
- 心跳前重新盘点实际容器状态，避免已崩溃容器仍被当作运行任务。
- 租约文件更新采用原子替换，避免看门狗读取到写入中间状态。
- 页面订单结束轮询返回关闭状态并停止轮询，不持续产生预期 410 网络错误。
