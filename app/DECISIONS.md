# 阶段 1 技术与产品决策

1. **范围**：本地模拟交易，不接真实 GPU、Docker、支付或任务执行。用户授权自行设计并开发后直接完成阶段 1，阶段 2 留待验收后推进。
2. **栈**：React 18 + Vite + React Router + 严格 TypeScript；Express 5 + zod 4；better-sqlite3 WAL。手写 CSS，无 UI 组件库。密码使用 bcryptjs 的 bcrypt 实现，避免额外原生密码依赖。
3. **金额舍入**：需求没有完整规定到分舍入，但给出 2 卡×200 分×65 秒≈7 分，因此采用总费用四舍五入到整数分，机主部分也四舍五入，平台取差额。整数除法使用正整数分子加半分母后向下取整；输入上限内运算在 JS 安全整数范围内。小额订单实际抽佣可能偏离 15%，不会创造或丢失分。
4. **最低一分钟**：实际秒数向上取整，至少 60 秒。65 秒仍按 65 秒计算，不能误写成只计 60 秒。示例中的“8.5 折”按机主分成理解，不给租客重复折扣。单卡 200 分×60 秒=3 分（四舍五入），文档中“约 4 分”为近似说明。
5. **占用**：BEGIN IMMEDIATE 锁住数据库写入→清理到期→重新读取余额和剩余卡位→创建订单与预付流水。SQLite 不提供行级锁；不存冗余剩余计数，按 running 订单聚合。挂牌总卡数和价格在阶段 1 创建后不可编辑，订单快照固定成交单价。
6. **结算**：写事务内 running→finished 条件更新，只有成功跃迁才退款与记供给收入。提前结束与定时扫描走同一函数。每 5 秒扫描，启动时补扫；结束时间裁剪到原到期时间。
7. **认证**：bcrypt 哈希；JWT 通过 HttpOnly、SameSite=Lax Cookie 传递；JWT 内随机 jti 的 SHA-256 写入 sessions 便于退出撤销。生产 Secure Cookie；签名密钥只取环境变量，开发未配置则仅内存生成。匿名可浏览，所有写请求 JSON 校验并检查 Origin/Fetch Metadata。认证接口按 IP 限速（单进程内存）。
8. **数据模型**：按交接包创建 users、sessions、machines、listings、orders、ledger 六表和索引，关联外键；阶段 1 虚拟机器状态 offline，不伪造心跳。machines 在挂牌时创建，为阶段 2 预留关系。
9. **演示**：种子机主随机不可知密码；不写入通用密码。体验入口创建独立随机账户，适合两个浏览器会话验收。新用户赠送仅为虚拟额度。开发重置要求登录、固定确认参数和界面二次确认。
10. **视觉**：以旧原型为方向重写，朱红印章、纸质公告牌、窄体等宽价格、衬线大标题、直角墨线与硬阴影。行情条形为装饰纹样，非历史数据图；统计数来自数据库。字体使用本地中文字体栈，避免外部字体网络依赖。移动端单列、导航横滑、流水表容器横滑。
11. **验证**：Vitest 接口测试使用独立内存数据库；另用临时文件验证关闭重开。Playwright 两个隔离 Cookie 上下文模拟机主与租客，四页手机视口检查及截图。页面不可自动伪造“真实 GPU 已连接”。

- 模拟 GPU UUID 唯一，非 released 分配记录有部分唯一索引；同一接入机器只允许一张挂牌。所有资源操作在立即写事务中执行。

- 增加 SQLite 版本迁移、升级前一致快照、在线备份命令、API 健康检查、请求 ID。迁移不重建或清空业务表。
- 前端提取 API、订单页和机器页；后端提取下单服务、接机路由、协议 schema 和迁移。认证与旧演示路由暂保留，避免无必要的大改。

## 2026-10-29：手动成果快照

- 后续授权继续开发时，选择先解决订单结束后结果丢失的问题。本轮新增免费内测存储规则：手动保存成功后保留 7 天、每单 3 份、每账户 64 MiB ZIP、单文件 1 MiB、每份原始文件 4 MiB / 100 个；不改变计费与分成。
- 只收集工作目录顶层可见普通文件。隐藏文件不保存，目录和链接使整份快照失败；避免用户误以为目录已完整备份。归档不是跨文件的全局原子快照，用户必须先保存并停止写入。Notebook 额外检查 JSON 完整。
- 沿用反向通道，容器读取、控制面校验并生成 stored ZIP。平台不解压用户 ZIP，不执行文件；清单、SHA-256 与 ZIP 作为 SQLite BLOB 在事务中保存，复用在线数据库备份流程。无新增 npm 依赖。
- 保存前后校验登录、租客、订单与工作台会话；每账户一个在途归档，落库再检查容量。归档不推迟容器销毁，结束时的迟到结果不保存。历史订单下载仍鉴权，只有租客能取回。
- 过期禁止访问，启动和每分钟补清理。逻辑删除不等于物理擦除，备份保留规则另行建设。当前不做自动归档、跨单恢复、目录递归、对象存储或真实收费。
- 数据库 v4 自动保存升级前快照，旧账户、订单、账本保留。旧 agent 需要重启读取新协议。

## 2026-10-29：单卡 PyTorch CUDA 终端

- 用户授权继续开发后，选择最小实际 GPU 计算切片：固定 PyTorch 2.10.0+cu128，在 ready 前执行 CUDA 矩阵乘法和自动求导；Python 和 JupyterLab + NumPy 模板保留，Notebook 不自动获得 GPU 框架。
- 模板仅允许 docker-gpu、机器登记单卡，订单显式分配一个 GPU UUID。按本地镜像 ID 启动，2 GiB 主内存、1 CPU、128 进程，沿用无网络、只读根目录、UID 1000 命令及租约看门狗。主内存额度不代表 GPU 显存隔离。
- 启动检查必须是固定只读脚本，CUDA 不可用时失败；失败清理当前容器。仅 root 可写租约目录的通过标记，避免重复投递破坏已经就绪的工作目录，或跳过中断的校验。用户目录中的可编辑 JSON 只代表实验结果，不当作可信审计凭证。
- PyTorch start 未回报重投间隔延长至 45 秒，容纳 30 秒检查上限及宿主 35 秒上限；总准备截止仍为 60 秒、最多两次。沿用 ready 后计费及准备失败全退，没有改动价格、分成和退款规则。
- 完整依赖版本、官方来源和 SHA-256 一同记录；下载使用有限并发分段并核对整包摘要，镜像通过 pip --no-index --require-hashes 离线安装。PyTorch 官方 Triton 与 PyPI 同版本包摘要不同，首次构建已按官方索引明确选择并锁定 PyTorch 发行包，不能作为同摘要镜像替换。
- 无数据库结构变化，仍为 v4。模板切换沿用空闲且已清理、撤销凭据、重新接入的规则。新增 gpu:check 命令和工作台示例入口，结果通过已有成果快照下载。
