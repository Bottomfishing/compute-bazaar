# 成果归档使用指南

本功能适用于受邀的 Docker CPU/GPU 租客，支持 Python 和 Notebook 模板。归档是手动保存的文件快照，不是自动备份，也不恢复计算内存或内核状态。

## 保存和取回

1. 在 Notebook 中按 Ctrl+S，确认输出已保存；停止继续写文件的任务。命令终端的结果需先写到 `/workspace` 文件中。
2. 在订单工作台找到“成果归档”，点击“保存成果快照”。只有出现“成果快照已保存”并列出文件和 ZIP 下载按钮，才表示平台保存成功。
3. 保存后可以结束租用。容器照常清理，不为归档延长计费或推迟销毁。
4. 在“我的订单”中点击该订单的“查看成果”，下载 ZIP。仅该订单租客登录后可下载，机主和其他用户不能下载。
5. 下载后可点击“删除快照”并确认，释放归档容量。删除不可恢复。

快照不会自动刷新。保存之后修改过的文件，需要再保存一份快照。未保存、保存失败或断线前未传回平台的文件，订单结束后无法取回。已经销毁的旧容器不能补归档。

## 内测规则

| 项目 | 当前限制 |
| --- | --- |
| 保留时间 | 从保存成功起 7 天，页面显示准确到期时间 |
| 每单数量 | 最多 3 份尚未过期的快照；删除后可在运行订单中重新保存 |
| 每文件 | 最多 1 MiB，文本、Notebook 和二进制均可 |
| 每份快照 | 最多 100 个文件，原始文件合计最多 4 MiB |
| 每账户容量 | 64 MiB，按 ZIP 实际字节计入，包括文件名与 ZIP 目录开销 |
| 收费 | 内测免费，不写入计费流水，不改变租金、预付或分成 |
| 文件范围 | `/workspace` 顶层可见普通文件；支持中文名 |
| 排除与失败 | 点号开头的隐藏文件忽略；目录、符号链接、FIFO 等特殊文件、无效名称、超限或读取时变化的文件使整份快照失败 |

Notebook 的 `.ipynb_checkpoints` 等隐藏内容不会保存。归档只包含文件，不包含虚拟环境、容器软件、GPU 内存、进程状态或整个容器镜像。已支持在新订单预览后恢复自己的历史快照，见[成果恢复指南](restore-guide.md)。当前不支持目录递归、选择部分文件、任意 ZIP 上传、自动到期快照、长期存储或对象存储。

## 校验和保留

agent 在订单容器内以 UID 1000 读取文件，通过现有认证反向通道传回。平台再次校验文件名、大小、规范 Base64 和 SHA-256，生成标准 UTF-8 ZIP（stored，不压缩），保存 ZIP、摘要和文件清单。下载响应含 `X-Archive-SHA256`，页面也展示摘要，可下载后核对。

仅运行且 ready 的订单可保存，必须同时有平台登录与有效工作台会话。会话过期需要重新打开工作台。归档前后重查访问权限；订单结束或退出登录时，在途结果不落库。每账户仅允许一个在途归档，保存后在同一数据库事务中再次检查容量。保存、删除会写入执行记录；失败不产生部分快照。

快照以 BLOB 保存在平台 SQLite 中。订单结束、agent 离线或容器删除不影响已保存快照。下载每次重新鉴权，不使用可公开分享的下载地址。到期立即禁止下载；服务启动、每分钟和归档读写时删除到期记录。服务关闭期间不会执行清理，重启后补清理。

删除和到期是在线数据库记录的逻辑删除。SQLite 可能复用空闲页而不缩小文件，历史备份也可能仍包含之前的快照；当前不承诺物理擦除或备份同步删除。上线前需要独立的备份保留与删除策略。

## 升级与接口

数据库版本 4 新增 `order_archives`，迁移前创建 `market.sqlite.before-v4.bak`，保留账户、订单和账本。运行旧版本 agent 时请重启 agent；无有效归档响应会明确报错。

- `GET /api/orders/:id/archives`：租客的快照清单、限制与账户已用容量。
- `POST /api/orders/:id/archives`：正文 `{session}`，复用有效工作台会话，手动保存。
- `GET /api/orders/:id/archives/:archiveId/download`：登录后下载 ZIP。
- `DELETE /api/orders/:id/archives/:archiveId`：正文 `{}`，删除指定快照。

依然是本机受控内测；尚未完成多主机存储、生产域隔离或 GPU 模型训练验证。
