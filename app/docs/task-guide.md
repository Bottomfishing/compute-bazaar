# 长时 Python 任务

在真实订单工作台先保存顶层 `.py` 脚本，再在“让脚本跑一会儿”选择文件、设置超时并提交。脚本最多 8 KiB、UTF-8；运行使用提交时读取的内容，后续编辑文件不会修改这次代码。

- 每单同时一个任务，超时 1–600 秒，默认 120 秒，每单最多提交 20 次。普通命令终端仍限 15 秒。
- 页面每 2 秒查询状态，显示运行、完成、失败、停止、超时或中断。刷新或关闭页面不停止任务；重新进入同一工作台可继续查看。
- 标准输出和错误合并，实时保留开头 16 KiB，超过后继续消费但不保存，并提示截断。可下载当前任务日志；仅保留最近一次任务，新任务会替换旧日志。
- 手动停止和超时停止会终止脚本进程组，不自动删除已生成文件。结果需手动归档；任务运行期间禁止归档和恢复，先停止或等待完成。
- 任务服从订单租约。订单结束、失败清理或 agent 退出会随容器销毁；文件、日志、状态一起删除。请在结束前下载日志和保存成果。
- 连接异常不代表已停止，请刷新状态核对。同一个请求 ID 重试不会重复启动；之前执行过的旧 ID 不会复活。不是持久化调度队列、跨订单自动续跑或模型训练服务。

适用于现有 Python、Notebook 和 PyTorch 模板的独立 Python 脚本。Notebook 内核运行是另一条执行路径，提交脚本不会共享内核变量。依赖仍由当前固定镜像决定。CPU 脚本已完成超过 15 秒的真实运行及停止测试；GPU 长任务资源压力测试、独立机主故障演练仍待完成。

## 升级

机主端重启接入命令加载 `agent-0.6.0`，无需重建镜像。现有旧容器请结束后新建订单，再使用长时任务。数据库仍为 v5，没有新增收费或改变结算、分成和退款规则。

## 实现与权限

复用订单工作台认证和反向连接，运行订单的 `task_start` / `task_status` / `task_stop` 均经登录租客、目标订单、有效会话检查。已关闭订单的状态查询只向登录租客返回空任务，不调用 agent，也不返回迟到日志；启动与停止仍拒绝。任务只在对应订单容器运行，不在控制面或宿主执行代码。任务记录在容器 root 私有 `/lease`，不是计费凭证；数据库不长期保存任务日志。

为允许 root 监督器启动 UID/GID 1000 子进程，容器在 `--cap-drop ALL` 后仅增加 `SETUID`、`SETGID`。实际脚本进程有效 capabilities 为 0，保留 `no-new-privileges`、只读根目录、无外网、无宿主挂载及原资源限制。监督器切换到 UID 1000 对子进程组发信号后恢复身份；任务代码不能读写 root 记录。root Python 管理与监督进程使用 `-I`，避免加载用户工作目录中的同名模块。实现依据 [Docker capabilities 文档](https://docs.docker.com/engine/containers/run/#runtime-privilege-and-linux-capabilities)和 [Python subprocess 身份切换文档](https://docs.python.org/3.12/library/subprocess.html#subprocess.Popen)，并有真实容器权限测试。

停止操作管理所启动的进程组，刻意创建新会话的程序可能脱离该进程组；整个容器仍服从订单租约。当前只开放受邀内测，不能将进程组管理当作面对恶意代码的独立隔离边界。
